# Security Policy

## Supported Versions

We actively maintain the following versions of CuraLink and provide security updates for supported releases.

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

Security fixes are prioritized for the latest stable release.

## Reporting a Vulnerability

If you discover a security vulnerability in CuraLink, please report it responsibly.

**Please do not disclose security vulnerabilities publicly through GitHub Issues, discussions, or pull requests.**

### How to Report

Please report vulnerabilities by opening a private security report through GitHub:

**GitHub → Security → Advisories → Report a vulnerability**

When reporting a vulnerability, please include:

* A clear description of the vulnerability
* Steps to reproduce the issue
* Potential impact
* Affected version(s)
* Any proof-of-concept, screenshots, or logs that help explain the issue

### Response Process

We will make reasonable efforts to:

1. Acknowledge the report within **7 days**.
2. Investigate and validate the reported vulnerability.
3. Keep the reporter informed about the investigation when appropriate.
4. Develop and release a security fix for confirmed vulnerabilities.
5. Credit the reporter in the security advisory if they wish to be acknowledged.

### Disclosure

Please allow us reasonable time to investigate and fix a confirmed vulnerability before publicly disclosing it.

Reports that are determined not to be security vulnerabilities may be declined with an explanation where appropriate.

Thank you for helping us keep CuraLink and its users secure.
